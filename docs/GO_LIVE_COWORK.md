# העלאה לאוויר והמעבר — הוראות עבודה ל-Claude Cowork

המסמך הזה נכתב בשביל **Claude Cowork** (Claude באפליקציית הדסקטופ, עם הדפדפן של דן).
המטרה: לסיים את החיבורים ואת ההעלאה, כדי שדן יוכל להפסיק לעבוד בדף ב-Claude ולעבוד רק מהמערכת החדשה.

- **מסלול:** Vercel + Supabase, מהדפדפן בלבד. אין שרת משלנו ואין טרמינל.
- **מסמכי רקע:**
  - `docs/CUTOVER.md` — מה נבדק ומה הסדר.
  - `docs/DEPLOY.md` — הסבר מלא לכל משתנה.
  - `docs/AI_QUEUE.md` — שגרת התור.

---

## חלק א' — מה רק דן עושה

אלה החלטות, אישורים וסודות. Cowork **לא** עושה אותם במקומו.

1. **למזג את PR #12 ל-main.** Vercel מפרסם רק מ-main. בלי המיזוג אין באוויר חתימות, ספריית טפסים וייבוא מדרייב.
2. **לבחור פרויקט Vercel אחד** מתוך הארבעה: danbubub, danbubub-app, danbubub-nfx6, danbubub-app12121.
   - ההמלצה: זה שכבר מחובר לריפו `dndbusiness/danbubub`, עם הבנייה האחרונה הירוקה מ-main.
   - את השאר לא מוחקים.
3. **לבחור כתובת** — דומיין משלך, או כתובת ה-`vercel.app` של הפרויקט. הכתובת הזו היא `APP_BASE_URL`, והיא חייבת להיות זהה בכל מקום.
4. **להזין בעצמך את הסודות** כש-Cowork עוצר ומבקש. Cowork לא רואה אותם, לא כותב אותם בצ'אט ולא שומר אותם בקובץ.
   - הסודות: `APP_PASSWORD`, `SECRETS_KEY`, `JOBS_SECRET`, `SIGN_SECRET`, `GOOGLE_CLIENT_SECRET`, ולפי הצורך `GREEN_API_TOKEN`, `ANTHROPIC_API_KEY`.
   - כל ערך: סיסמה אקראית ארוכה ממנהל הסיסמאות (32+ תווים).
   - לשמור עותק במנהל הסיסמאות. **אם `SECRETS_KEY` הולך לאיבוד, החיבור לגוגל נשבר.**
5. **לאשר את המסך של גוגל** ("Google hasn't verified this app" ← Advanced ← Go to…). זה החשבון שלך.
6. **יום המעבר:** אתה מחליט מתי, ואתה לוחץ **"עוברים לעבוד מכאן"**.
7. **שגרות של Claude:** לאשר את שגרת התור ואת החלפת בדיקת הגיבוי הלילית (חלק ב', שלב 11).
8. **בטלפון, במשרד:** הגדרות ← שעון נוכחות ← "קבע משרד לפי המיקום שלי".

## חלק ב' — ההוראות ל-Cowork

### כללים — לפני הכל

- **סודות:**
  - לא מקלידים, לא מדביקים ולא מצלמים סודות.
  - בשדה של סוד — עוצרים ואומרים לדן: "הדבק כאן את X".
  - לא כותבים ערכים של סודות בצ'אט, בקבצים או בהערות.
- **מה לא עושים בכלל:**
  - לא ממזגים PR.
  - לא מוחקים פרויקט Vercel, artifact, קובץ או תיקייה.
  - לא נוגעים בתרחישי Make, בגיליון "מעקב לידים", בתיקיות של WISE בדרייב, או במשתני סביבה של שלושת הפרויקטים האחרים.
- **"עוברים לעבוד מכאן"** — רק אחרי ש-דן כתב במפורש "עוברים". הפעולה סוגרת את הייבוא מהדף הישן.
- **אחרי כל שלב:** מריצים את הבדיקה שכתובה בו ומדווחים לדן בעברית — מה נעשה, מה הבדיקה הראתה, מה הבא.
- **כשמשהו לא מתאים להוראות:** עוצרים ושואלים. לא מנחשים ערכים.

### שלב 4 — משתני סביבה (Production)

Settings ← Environment Variables. **הערכים הסודיים — דן מדביק.**

| משתנה | מי מזין | ערך |
|---|---|---|
| `APP_PASSWORD` | דן | סיסמת הכניסה למשרד |
| `SECRETS_KEY` | דן | אקראי, 32+ תווים |
| `JOBS_SECRET` | דן | אקראי, 32+ תווים |
| `SIGN_SECRET` | דן | אקראי, 32+ תווים |
| `APP_BASE_URL` | Cowork | `https://<הכתובת>` — בלי `/` בסוף |
| `CHROMIUM_PACK_URL` | Cowork | הערך מ-`docs/DEPLOY.md` §3 (קישור לחבילת Chromium ב-GitHub) |
| `OWNER_EMAIL` | Cowork | המייל של דן במשרד (לשאול את דן) |

**לא חובה עכשיו (לשאול את דן):**
- `GREEN_API_ID_INSTANCE` + `GREEN_API_TOKEN` — וואטסאפ.
- `ANTHROPIC_API_KEY` + `AI_DAILY_ILS=15` — דן אישר תקרה של 15 ₪ ליום.
- `LEADS_API_KEY` — קליטת לידים חיצונית.
- `VOICENTER_SECRET` — שיחות.

**אחרי השמירה:** Deployments ← האחרון ← Redeploy.
**בדיקה:** `<הכתובת>/api/health` מחזיר 200, או הודעה שהסכימה חסרה — שתיהן תקינות בשלב הזה.

### שלב 6 — חיבור גוגל

ב-[Google Cloud Console](https://console.cloud.google.com), עם חשבון הגוגל של המשרד שדן עובד ממנו (מייל, דרייב, יומן):

1. פרויקט חדש: `harel-system`.
2. APIs & Services ← Library ← **Enable** ל-4 ממשקים: Gmail API, Google Calendar API, Google Drive API, Google Sheets API.
3. OAuth consent screen:
   - **חשבון Google Workspace:** סוג **Internal**.
   - **חשבון @gmail.com:** סוג **External**.
     - ב-Test users מוסיפים את המייל של דן.
     - בסוף: **Publish app ← In production**. לא מגישים לאימות.
     - **חשוב:** במצב Testing גוגל מנתק את החיבור כל 7 ימים.
   - שם האפליקציה: "הר-אל — מערכת". מייל תמיכה: המייל של דן.
4. Credentials ← Create credentials ← OAuth client ID ← **Web application**:
   - Authorized redirect URIs: `https://<הכתובת>/api/google/callback` — בדיוק כמו `APP_BASE_URL`.
5. מעתיקים את **Client ID** ל-`GOOGLE_CLIENT_ID` ב-Vercel.
6. דן מדביק את **Client secret** ל-`GOOGLE_CLIENT_SECRET` ב-Vercel ← Redeploy.
7. `<הכתובת>/settings` ← כרטיס גוגל:
   - כל השירותים מסומנים, **כולל "CRM — טבלאות הלידים ותיקיות הלקוחות בדרייב"**. זו הרשאת Drive מלאה, ובלעדיה אין ייבוא טפסים מדרייב ואין תיקיות לקוחות קיימות.
   - "חבר את גוגל" ← דן בוחר חשבון ומאשר.

**בדיקה:** בכרטיס גוגל מופיע החשבון המחובר וכל ההרשאות.

### שלב 7 — הג'ובים והשומר (GitHub Actions)

1. GitHub ← הריפו ← Settings ← Secrets and variables ← Actions ← New repository secret. **דן מדביק את הערכים** — אותם ערכים כמו ב-Vercel:
   - `APP_BASE_URL`
   - `APP_PASSWORD`
   - `JOBS_SECRET`
2. Actions: אם הזרימות כבויות — Enable.
3. מריצים ידנית:
   - **crm-keeper** ← Run workflow. צפוי ירוק. במצב שכפול הוא מדלג, וזה תקין.
   - **cron** ← Run workflow ← `alerts_eval`. צפוי ירוק.

**בדיקה:** שתי ההרצות ירוקות. ב-`/settings` ← "בריאות המערכת" מופיעה ריצה.

### שלב 8 — חזרה גנרלית על הנתונים (לא המעבר עצמו)

2. במערכת החדשה, בפס "מצב שכפול" ← **"עדכן מקובץ גיבוי"** ← בוחרים את הקובץ.
3. משווים ספירות בין הדף הישן למערכת החדשה: לידים, לקוחות, משימות, תנועות, אנשי קשר. צריכות להיות זהות.

**בדיקה:**

- עוברים על המסכים: בית, לידים, לקוחות, משימות, כסף, טפסים, הגדרות. בלי שגיאות.

   - בסוף עוברים עם דן על הטפסים המסומנים "לבדיקה": "שדות" ← לבדוק ← שמור.

3. **שעון נוכחות:**
   - הגדרות ← שעון נוכחות ← "וואטסאפ ומייל למנהלים".
   - מיקום המשרד — דן, מהטלפון, במשרד.
4. **בדיקה סופית:**
   - `/api/health` = 200.
   - `/settings` ← "בריאות המערכת" בלי אדום.
   - שליחת מסמך לחתימה לדן עצמו: הקישור נפתח מהטלפון והמייל הגיע.

## חלק ג' — מערכת הכספים (אחרי ה-CRM, לא חוסם את המעבר)

- **הקובץ של הר-אל:** `<הכתובת>/import` ← "קובץ האקסל של הר-אל" ← הקובץ האמיתי מדן. ריצה חוזרת = 0 שורות חדשות.
- **יעדי מסירה:**
  - `/alerts` — מייל ווואטסאפ של דן. בלעדיהם שום התראה לא יוצאת.
  - `/settings` — מייל רו"ח, ניסים והדס.
- **עוגן:** `/anchor` — יתרת הבנק של היום.
- **קודי PIN** (ניסים / שותפים / פרייבט):
  - אין להם מסך. מוגדרים רק מטרמינל, עם `DATABASE_URL` של Supabase: `node scripts/set-pin.mjs <אזור> <קוד>`.
  - דן מקליד את הקוד בעצמו. מתאים ל-Claude Code על המחשב של דן, לא ל-Cowork.
