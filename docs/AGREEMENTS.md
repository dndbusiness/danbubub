# ספריית ההסכמים — מוכן לשליחה

**מה נבנה (17/10, לבקשת דן "להכין את כל ההסכמים לשליחה"):** כל ההסכמים של הר-אל מהדרייב הומרו לתבניות מוקלדות
בתוך המאגר (`data/agreements/*.md`), עם שדות שמתמלאים מהכרטיס. בהגדרות של ה-CRM יש כפתור אחד שטוען את כולם,
כל הסכם נכנס **כטיוטה** ולא נשלח עד שדן לוחץ "אשר נוסח". בכרטיס הלקוח ההסכם המתאים מוצע לפי המוצר.

> הנוסחים הם של דן — שונה רק מה שחייב: פרטים של לקוח הוחלפו בשדות, תיבות סימון הפכו לשדה, שורות "חתימה: ____"
> הוסרו (החתימה נעשית בדף החתימה). כל שינוי מעבר לזה רשום בעמודת "הערה" ובתוך הטיוטה עצמה. **מומלץ שעו״ד יעבור על
> כל נוסח לפני "אשר נוסח".**

## 2. איך מאשרים ושולחים

1. **הגדרות ← "ספריית תבניות לחתימה" ← "טען את ספריית ההסכמים"** (בעלים בלבד, רק במערכת בשרת). מוצגת טבלה:
   נוסף כטיוטה / עודכן / ללא שינוי / **דורש אישור לדריסה** (הסכם שערכת, אישרת או מחקת — נדרס רק אם מסמנים, והנוסח
   הקודם נשמר ב-`prevBody`). טעינה חוזרת לא משנה דבר.
2. בכל שורה עם "טיוטה" — **"אשר נוסח"**: הנוסח המלא, השדות מסומנים בשמם, הערת ההמרה. האישור מוריד את סימון הטיוטה
   ורושם מי ומתי (`approvedAt`, `approvedBy`, `approvedVersion`). סימון `[טיוטה` שכתבת בעצמך בתוך הנוסח — נשאר וחוסם.
3. בכרטיס הלקוח ← "שלח מסמך לחתימה": ההסכם המתאים למוצר נבחר מראש ("התבנית הוצעה לפי המוצר"), השדות מתמלאים מהכרטיס,
   מה שחסר — באדום. "שלח לחתימה" ← קישור אישי לכל חותם (מייל דרך ה-outbox + כפתור וואטסאפ מהטלפון).
   גם "החתמה" מכרטיס הרכב בקליטה משתמשת עכשיו בהסכם הרכב (לא בהסכם הכללי).
4. **השרת דוחה נוסח טיוטה** (`[טיוטה`) גם אם הדף לא חסם — `POST /api/sign` מחזיר 422.

## 3. טפסים של גופים אחרים (PDF) — להעלות ידנית

אלה טפסים של הבנק / הקרן / חברת המימון — לא נוסח של הר-אל, ולכן הם **טופסי PDF** ולא תבנית מוקלדת: מעלים את ה-PDF
המקורי ומציבים שדות. **בהגדרות ← "טפסים מ-PDF" ← "+ טופס"** (או בכרטיס ← "מסמך מזדמן"). כל העותקים בדרייב כבר
ממולאים בפרטי לקוח — **צריך עותק ריק מהגוף עצמו**.

| טופס | סוג / תיקייה | חותמים | הצבת שדות מוצעת |
|---|---|---|---|
| כתב הרשאה וייפוי כוח לטובת יועץ משכנתאות — פריסבי מימון (7 עמודים) | בנק ← "מימון ישיר" | 2 לווים | עמ׳ 1: שם + ת״ז לכל לווה בראש ("פרטי הלווים"). עמ׳ 3: טבלת "חתימות הלווים" — שם, ת״ז, חתימה, תאריך לכל לווה (שורה לכל לווה). עמ׳ 4 נספח א׳ (ויתור סודיות): שם + ת״ז + חתימה + תאריך לכל לווה. עמ׳ 5 נספח ב׳ (דיוור ישיר): 4 תיבות סימון (טלפון / מייל / וואטסאפ / מסרון) + חתימה + תאריך. עמ׳ 6-7 נספח ג׳ (ייפוי כוח לדוח נתוני אשראי): פרטי הלקוח + חתימה + תאריך. **"אימות חתימה" בעמ׳ 3 — של היועץ (דן), לא של הלקוח**: למלא לפני ההעלאה או להשאיר |
| כתב הרשאה ליועץ — LOANWISE | בנק ← "מימון ישיר" | 1-2 | לפי אותו מבנה; לבדוק בעותק ריק |
| טופס הסכמה למסירת נתוני אשראי / להוצאת דוח אשראי | בנק ← לפי הבנק | 1-2 | שם, ת״ז, חתימה, תאריך לכל לווה; קוד אימות מומלץ |
| טופס בקשת הלוואה — לווים פרטיים (פמה) | בנק ← "מימון ישיר" | 2 | מומלץ קודם להמיר את ה-docx ל-PDF |
| ייפוי כוח (BGR, נוטריוני, משכון מקרקעין — קרגו) · הודעת רישום משכון (טופס 1) | ייפוי כוח | לפי הטופס | **ייפוי כוח נוטריוני ורישום משכון דורשים אימות עו״ד/נוטריון — לא מספיק חתימה אלקטרונית** |
| טופס בלעדיות (PDF המקורי) | הסכם התקשרות (נדל״ן) | 1 | אם מעדיפים את הטופס המעוצב על פני `realestate-exclusivity`: שם, ת״ז, תאריך בראש; חתימה בתחתית; שם הפרויקט/יזם/עיר כשדות טקסט בכל שורה |

המיקומים בטבלה הם לפי מבנה הטקסט בעותקים שבדרייב — קואורדינטות מדויקות (x/y) לא חושבו, כי אין עותק ריק. בעורך השדות
גוררים כל שדה למקומו על הטופס עצמו.

**לא נכנסו לספרייה ולמה:**
- `1LYzOke…` (שעבוד רכב מקוצר v1), `1D59T4F…` (תוכנית עסקית — הגרסה הישנה) — יש גרסה חדשה יותר.

## 4. התשתית — מה נבדק ומה תוקן

| רכיב | מצב |
|---|---|
| קישור לחותם `/s/<token>` | עובד — טוקן אקראי (נשמר רק ה-hash), תוקף 14 יום, נתיב פתוח ב-middleware. נבדק בטלפון (390) בלי גלילה אופקית |
| טיוטה | **תוקן:** השרת דוחה נוסח עם `[טיוטה` (לפני כן רק הדף חסם) |
| שדות רשות | **נוסף:** `{{שדה?}}` — בן/בת זוג לא חוסם שליחה כשאין |
| קוד אימות (OTP) | במייל דרך ה-outbox. **נוסף:** חותם בלי מייל מקבל קוד **בוואטסאפ** (Green-API, דרך ה-outbox) כשמוגדר; אחרת חותם בלי קוד — ויש על כך הודעה בשליחה (במקום שהדף יוריד את הקוד בשקט) |
| PDF של נוסח מוקלד | Playwright ← `stored_files`. ב-Vercel דורש `CHROMIUM_PACK_URL`; בכל סביבה דורש `SIGN_SECRET` (או `APP_PASSWORD`) — בלעדיו עמוד ההדפסה נחסם וה-PDF נכשל ("צור PDF שוב" בכרטיס) |
| שמירה בדרייב | תיקיית הלקוח ← "הסכמי התקשרות" (לפי סוג). דורש חיבור גוגל (ב.1, scope drive) ותיקייה ללקוח |
| עותק במייל | לכל חותם + לדן, דרך ה-outbox (dedup). דורש חיבור גוגל עם `gmail.send` — אחרת ממתין ב-outbox |
| מצב | נשלח / נפתח / חלק חתמו / נחתם / פג תוקף / בוטל — בכרטיס ובמסך "מסמכים לחתימה" |
| ביטול / שליחה חוזרת | "בטל" בכרטיס; "תזכורת" = קישור חדש (הישן מפסיק לעבוד) + מייל |
| תזכורת אוטומטית למי שלא חתם | **לא נבנתה** — אין לה ג׳וב בחלק ג׳ של ה-ADDENDUM (כלל 14). היום: כפתור "תזכורת" ידני. אם רוצים אוטומטי — דן צריך להוסיף לחלק ג׳ |
| הזמנה בוואטסאפ אוטומטית | בכוונה לא — הקישור נשלח מהטלפון של דן (כפתור וואטסאפ בכרטיס). אפשר להוסיף דרך Green-API אם דן רוצה |
| חתימת החברה | הדף מחתים רק את הלקוח/הלווים. "חתימת החברה" שבמקור — לא קיימת בזרימה; השליחה מטעם החברה והתיעוד בעמוד האחרון |

## 5. הגדרות שדן צריך לוודא בשרת

| משתנה / פעולה | למה |
|---|---|
| `APP_BASE_URL` | הכתובת בקישור לחותם |
| `SIGN_SECRET` (או `APP_PASSWORD`) | ה-PDF החתום. בלי — אין PDF |
| `CHROMIUM_PACK_URL` (Vercel) | ה-PDF החתום ב-serverless — `docs/DEPLOY.md` §3 |
| חיבור גוגל ב-/settings עם `gmail.send` + Drive | הזמנה, קוד אימות ועותק חתום במייל; שמירה בדרייב |
| `GREEN_API_ID_INSTANCE` + `GREEN_API_TOKEN` | קוד אימות בוואטסאפ לחותם בלי מייל (לא חובה) |
| מצב ה-CRM `live` | ההגדרות נכתבות בשרת. במצב `mirror` (שכפול מהדף ב-Claude) ייבוא הגיבוי הבא ידרוס את הספרייה שנטענה — לטעון אחרי המעבר |

## 20/10 — ההסכמים הקבועים של דן, שטר חוב, חותמת החברה

**ההסכמים** — דן שלח אותם כקבצים (`providedBy: dan`). הם נטענים מאושרים, בלי שלב "אשר נוסח":

| סוג | הסכם קבוע | קובץ |
|---|---|---|
| נכסים | הסכם למתן שירותים — הלוואה כנגד שעבוד נכס | `finance-property-pledge-loan` (גרסה 2) |
| עסקים | הסכם מתן שירותים — תוכנית עסקית וגיוס אשראי | `finance-business-plan` (גרסה 2, הנוסח המלא) |
| רכב | כתב מינוי יועץ פיננסי | `finance-car-advisor` |

הבחירה האוטומטית לפי סוג (`FIXED_DEFAULT` בדף) — אפשר לשנות בהגדרות ← "הסכם קבוע לפי סוג".

**שטר חוב** — `finance-promissory-note` (`attachment: true`, לא מופיע ברשימת התבניות):
- בשליחה מסמנים "צרף שטר חוב" ורושמים סכום.
- הסכום במילים מתמלא לבד (`lib/rules/hebrew-number.ts`, זהה ל-`heNumWords` בדף).
- השטר נכנס אחרי `@@עמוד חדש@@`, עם אותה חתימה ואותה חותמת.

**סימונים בנוסח:**
- `@@חתימות@@` — מקום חתימה. בדף החתימה: "כאן תופיע החתימה שלך" + חותמת. ב-PDF: חתימת הלקוח + חותמת החברה.
- `@@עמוד חדש@@` — מסמך מצורף מתחיל בעמוד חדש.
- שורה שכל השדות בה רשות וריקים (בן/בת זוג, ערב) לא מוצגת.

**הערות החברה** — בכל הסכם יש סעיף "הערות" בסוף ("אין הערות." כשריק):
- ההערות נכתבות בשליחה.
- כשמצורף שטר חוב, ההערות נכנסות לפני השטר.

**חותמת החברה:**
- דן מעלה פעם אחת בהגדרות ← "חותמת החברה". הרקע מנוקה בדפדפן ונשמר PNG שקוף.
- הקבצים: `/api/sign/stamp`, `lib/sign/stamp.ts`.
- כל מסמך שומר את החותמת של רגע השליחה (`@stamp`).

**תיעוד:**
- **נשמר כבר קודם:** IP, מכשיר, קוד אימות, ת"ז מול הכרטיס, טביעות SHA-256.
- **נוסף:** "הקישור נמסר — בוואטסאפ ל-05X / הועתק להעברה ידנית · ע"י <מי>" בציר הזמן ובעמוד התיעוד (`markShared`).
